# tools/ —— 开发期辅助脚本

这里的脚本**不参与** `pytest` 收集，也不打进入 APK，只在开发机上手动运行。

## ui_smoke_headless.py —— Kivy 无头 UI 冒烟测试

### 为什么需要它
本项目踩过一个反复出现的坑：**代码语法编译通过、单元测试全绿，但真机一打开就闪退
或界面看不见字**。原因是纯逻辑测试覆盖不到 UI 层的问题，例如：

- 控件属性名写错 / 控件缺失；
- `size_hint` 没被父容器解析，控件尺寸停在默认 `100×100`；
- 控件位置被算到屏幕外（历史 bug：首页入口卡片标题被推出屏幕，看起来就是"按钮无字"）；
- 某个页面 `build()` 抛异常。

这个脚本会**真的建立一个 Kivy 窗口**（在虚拟显示里），构建完整控件树、跑一次布局、
模拟点击与填表，把上面这些纯 UI 层错误提前抓出来。

### 前置条件
需要一个真实的显示环境。纯 `SDL_VIDEODRIVER=dummy` / `KIVY_WINDOW=mock` 这类方案
**在 Kivy 2.3.0 上行不通**（sdl2 窗口后端仍会去连 X server 并报
`Couldn't connect to X server`），必须用 Xvfb 提供虚拟显示：

```bash
apt-get install -y xvfb        # 提供 /usr/bin/Xvfb 与 /usr/bin/xvfb-run
```
Mesa 软件渲染（llvmpipe）会自动兜底提供 OpenGL，无需独显。

### 运行方式
```bash
cd <项目根目录>
xvfb-run -a -s "-screen 0 1080x2400x24" python3 tools/ui_smoke_headless.py
```
脚本内部按自身 `__file__` 推导项目根目录，所以从任何工作目录运行都可以。

### 判定标准
- 退出码 `0`：全部断言通过；
- 退出码 `1`：存在失败项。脚本末尾会打印 `通过: N 项 / 失败: M 项` 并逐条列出失败项名字。

### 覆盖范围（共 9 组、128 项断言）
1. 启动 App 并 `build()` 出 `ScreenManager`，首页创建成功；
2. **首页入口卡片几何体检**：四张卡片高度 78dp、宽度=屏宽-32dp、背景层/文字层铺满卡片、
   标题 Label 落在卡片矩形内且在屏幕内（直接回归"按钮无字"老 bug）；
3. 点击四个入口能正确切页、控件树非空、能回首页；
4. 分段重命名页 13 个控件契约，以及各页「预览 / 执行 / 返回键(‹)」齐全；
5. 分段页「文字区/数字区」模式联动灰化逻辑；
6. 参数校验的中文提示文案；
7. 端到端：设文件夹 → 预览（无冲突）→ 执行改名 → 撤回还原；
8. 未选文件夹时点预览/执行不崩（兜底）；
9. `refresh_folder_labels` 全局刷新不崩且各页 `plan` 被清空。

### 注意
- 脚本会在系统临时目录下建测试文件夹并自清理，不会碰你的真实文件；
- 运行后项目根目录可能出现 `crash.log`（崩溃兜底机制的标记文件，已在 `.gitignore` 内）；
- 真机验证**不可被它替代**：它跑在桌面 Kivy + 软件渲染上，能拦大部分布局/属性类错误，
  但真机特有的权限、签名、厂商 ROM 差异仍需装机实测。

## render_segment.py —— 分段重命名页「真机尺寸」渲染脚本

### 为什么需要它
布局代码看起来没问题，不代表真机首屏能看到关键信息。`ui_smoke_headless.py` 只验证
「控件存在、尺寸非零」，验证不了「参数卡太长、示例行被推出首屏」这类视觉问题。
本脚本按真机密度把页面**真的渲染成 PNG**，供肉眼 / OCR 复核。

### 产物（输出到 `tools/shots/`，该目录不入库）
| 文件 | 尺寸 | 说明 |
|---|---|---|
| `viewport_<模式>0001.png` | 1080×2400 | 真机首屏，`Window.screenshot()` 取得 |
| `fullpage_<模式>.png` | 1080×高 | 整页，用 `Fbo` 直接画 `page` 子树，不受 ScrollView 裁剪 |

### 运行方式
```bash
cd <项目根目录>
KIVY_METRICS_DENSITY=2.8125 xvfb-run -a -s "-screen 0 1080x2400x24" \
    python3 tools/render_segment.py
```
脚本内部按 `__file__` 推导项目根目录，从任何工作目录运行都可以。

### 判读方法
脚本末尾会打印每张整页图的高度。**整页高 > 2400 说明真机上必须滚动**；
差值就是还要往下滑的像素数。

### 坑
- 跑前先 `pkill -9 -f Xvfb`（软件渲染吃内存，残留进程叠加会被 OOM 杀，日志只剩 `Killed`）；
- 显示环境必须是 Xvfb，理由见上一节。

## screen_heights.py —— 四页高度对比体检

轻量版：只建窗 + 跑布局，**不渲染、不截图**，内存压力小、跑得快。它按真机密度
逐页量出「ScrollView 视口高 vs page 内容高」，打印四页对照表，快速定位哪一页是
「体验洼地」（历史上分段页超出 1380px）。

运行方式与 `render_segment.py` 相同（都要 Xvfb + `KIVY_METRICS_DENSITY=2.8125`）：
```bash
KIVY_METRICS_DENSITY=2.8125 xvfb-run -a -s "-screen 0 1080x2400x24" \
    python3 tools/screen_heights.py
```

用途：**任何布局改动后都重跑一次做前后对比** —— 只有目标页的高度应该变化，
其余页数据应一字不变（用来证明改动无副作用）。
