# 批量重命名 · Batch Renamer

**在安卓手机上把一堆文件批量改名的小工具**——不用一个个手点。

基于 Kivy / Python 写的手机 App，配套一套纯命令行版本。核心原则是**"每页只做一件事"**：
四个功能页彼此完全独立，各页设置互不影响，每页都有自己的预览计划，不会出现"A 页预览、B 页执行"的串台。

### 装机两句提醒

1. **如果装过旧版本，先卸载再装**。构建用的签名换过，直接覆盖安装会报"应用未安装"。
   卸载只会清掉 App 自己内部的设置，**不会动你手机里的任何文件**。
2. **首次启动要给权限**：存储权限 +「所有文件访问权限」（管理所有文件）。
   不给的话，选完文件夹列表会显示"约 0 项"——不是没读到，是被系统挡住了。

## 二、能干啥

首页是四个入口，点进去就是一个专做一件事的页面：

| 页面 | 做什么 | 可调参数 |
|---|---|---|
| **加前/后缀** | 在文件名最前面加前缀、在扩展名之前加后缀 | 前缀文本、后缀文本（都留空则不加） |
| **查找替换** | 把文件名里匹配到的文字换掉，或删掉 | 被替换内容、替换成什么（留空 = 删除） |
| **插入序号** | 给文件批量编号 | 起始数字、每次加几、序号位数、位置（0=开头 / 1=末尾） |
| **分段重命名** | 把文件名拆成「文字 + 数字」两段，分别重排 | 文字区与数字区各自的递增 / 固定文本、起始值、步长、位数、排序依据、两段之间的分隔符 |

**每个功能页都自带一整套公共操作区**：

```
选择文件夹  →  预览  →  执行  →  撤回
```

- **预览**：只列出"打算改成什么"，绝不碰你的文件；
- **执行**：真正的改名动作；
- **撤回**：按操作日志把名字还原回去。

### 安全设计（写代码时就防着你手滑）

- **冲突保护**：出现"两个文件要改成同一个名字"或"会覆盖已存在的文件"时，直接拒绝执行；
- **原子性**：采用"先改临时名 → 再改最终名"两步法，中途出问题会自动回滚，不留半截状态；
- **目录隔离的日志**：不指定日志路径时，日志写在目标目录下，不同目录互不覆盖。

### 举个例：分段重命名

文件名形如 `旅行照片001.jpg`、`旅行照片002.jpg`……想按"文字照旧、数字从 100 开始每次 +1、补足 3 位"重排：

```
文字区：固定文本 = 旅行照片
数字区：起始 = 100，每次加 = 1，位数 = 3
分隔符：留空（两段直接相接）
→ 旅行照片100.jpg、旅行照片101.jpg、旅行照片102.jpg …
```

想改成 `IMG1_100.jpg` 这种带连接符的，把分隔符填上 `_` 即可。

## 三、命令行版本（顺手也能用）

不装 App，在电脑上也能用同一套逻辑：

```bash
# 预览：在 ./photos 里给所有文件加前缀
python -m batch_renamer.cli ./photos --prefix "vacation_" --dry-run

# 确认无误后执行
python -m batch_renamer.cli ./photos --prefix "vacation_"

# 撤回上一次操作
python -m batch_renamer.cli ./photos --undo
```

参数与退出码约定（`0` 成功 / `1` 失败或有冲突，方便写进脚本）详见
[batch_renamer/README.md](batch_renamer/README.md)。

## 四、项目结构

```
main.py                     Kivy 界面：首页 + 四个功能页（界面与交互）
batch_renamer/
    core.py                 重命名计划与执行、冲突检测、回滚、日志
    operations.py           各种重命名操作（前缀/后缀/替换/序号/分段）
    cli.py                  命令行入口
    ui_utils.py             界面公共小部件与工具
tests/                      单元测试（pytest）
tools/                      开发期辅助脚本（不参与测试收集、不打进 APK）
buildozer.spec              安卓打包配置
signing/debug.keystore      固定调试签名（保证各版本可覆盖安装）
.github/workflows/build.yml CI：push 到 main 自动构建 APK
fonts/                      内置中文字体
```

## 五、自己构建

### 云端（推荐，不折腾环境）

push 到 `main` 即自动触发 GitHub Actions（工作流 `Build APK`），
产物在本次运行的 Artifacts 里，名字 `batch-renamer-apk`。
现在仓库是公开的，Actions 分钟数不限。

> CI 里有两处值得一说的踩坑修复，都写在 `build.yml` 的注释里：
> 一是固定调试签名（避免每个版本签名不同导致覆盖安装失败），
> 二是给 python-for-android 旧模板注入 `mavenCentral()`（AGP 8.1.1 的传递依赖只发在 Maven Central，旧模板不认）。

### 本地

```bash
pip install buildozer cython
buildozer android debug        # 产物在 bin/
```

### 跑测试

```bash
pytest -q                                       # 逻辑单元测试
# UI 层冒烟（需要 Xvfb 提供虚拟显示）
xvfb-run -a -s "-screen 0 1080x2400x24" python3 tools/ui_smoke_headless.py
```

`tools/` 下还有两个"布局体检"脚本（真机尺寸渲染成 PNG、四页高度对照），
用途是防止"代码能跑但真机上看不见字/关键信息被挤出首屏"，详见 [tools/README.md](tools/README.md)。

## 六、已知限制

- 只改文件名本身，**不移动、不删除目录**；
- 撤回依赖操作日志，日志丢了就撤不回来；
- 目前是**调试签名**的包，仅供自用与测试，不适合上架应用商店；
- 逻辑测试与 UI 冒烟都跑在桌面环境（模拟显示 + 软件渲染），
  能拦住布局/属性类问题，但真机特有的权限、厂商 ROM 差异仍需装机实测。
